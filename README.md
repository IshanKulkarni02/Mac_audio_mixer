# AudioMixer

A macOS audio mixer: a virtual output device that any app can play into, plus
per-application and hardware input strips that get mixed, processed, and routed
from a native SwiftUI control surface.

The DSP core is Rust, the driver is a user-space Core Audio HAL plugin (no kernel
extension), and the UI is SwiftUI. Nothing here is copied from an existing driver —
the plugin is written against Apple's public `AudioServerPlugIn.h` contract.

> **Status: early.** The pieces build and load independently, but they are not
> wired together yet. See [Status](#status) for exactly what works today.

## Concept

macOS treats system audio as one stream: whatever the current output device is
gets everything, mixed by the OS with no per-app control. AudioMixer turns that
into a small mixing console. Each source — a per-app process tap, the
microphone, eventually a network input — becomes its own strip with its own
gain and mute, mixed down in a real-time-safe Rust core, and pushed out through
a virtual Core Audio device ("AudioMixer Output") that any app can select as
its output, the same way a hardware audio interface would show up.

The point is control and routing that the OS doesn't give you by default: mute
one app's audio without touching the system volume, blend the mic in at a
different level than playback, and hand the combined signal to something else
(a recorder, a streaming tool, another output) as a single selectable device —
without a kernel extension, since the driver is a user-space
`AudioServerPlugIn`.

## Architecture

```
┌──────────────┐   selects as output    ┌─────────────────────────┐
│  Any app     │ ─────────────────────► │ HALPlugin               │
│ (Music, …)   │                        │ "AudioMixer Output"     │
└──────────────┘                        │ 2ch · f32 · 48 kHz      │
                                        └───────────┬─────────────┘
┌──────────────┐   CATapDescription                 │ ring buffer
│  Per-app     │ ─────────────────────►             ▼
│  process tap │                        ┌─────────────────────────┐
└──────────────┘                        │ RustCore                │
                                        │ dsp-engine (mix, gain)  │
┌──────────────┐   AVAudioEngine        │ mixer-ffi (C ABI)       │
│  Microphone  │ ─────────────────────► └───────────┬─────────────┘
└──────────────┘                                    │ FFI
                                                    ▼
                                        ┌─────────────────────────┐
                                        │ App (SwiftUI)           │
                                        │ strips, gain, mute      │
                                        └─────────────────────────┘
```

Real-time rules the core follows: no allocation, no locks, and nothing blocking on
the audio thread. Producer→consumer handoff is a lock-free SPSC ring buffer with
exactly one producer (a tap, mic, or network source) and exactly one consumer (the
render callback).

## Layout

| Path | What it is |
| --- | --- |
| `RustCore/dsp-engine` | Mix math (per-strip dB gain, mute) and the lock-free ring buffer. Unit-tested, no audio hardware needed. |
| `RustCore/ffi` | `mixer-ffi` — the C ABI both the driver and the app link against. Header generated by cbindgen into `ffi/include/mixer_ffi.h`. |
| `HALPlugin` | `AudioServerPlugIn` in C that publishes the virtual output device. Built into `build/AudioMixer.driver`. |
| `App` | SwiftUI control surface (SPM executable, macOS 14.4+). |
| `Spikes/ProcessTapSpike` | Phase 0 feasibility test for `CATapDescription` + `AudioHardwareCreateProcessTap`, including whether `muteBehavior` prevents double-audio. |
| `Installer`, `Scripts` | Empty placeholders for packaging/install tooling. |

## Requirements

- macOS 14.4 or later (process taps need it)
- Xcode command line tools (`clang`, `codesign`, Swift 5.10)
- Rust toolchain (2021 edition)

## Build

**Rust core** — builds both crates and generates the C header:

```bash
cd RustCore && cargo build && cargo test
```

**HAL plugin** — compiles the bundle and ad-hoc signs it (coreaudiod refuses to
load an unsealed bundle, so the `codesign` step is not optional):

```bash
cd HALPlugin && make
```

**App**:

```bash
cd App && swift run MixerApp
```

**Process tap spike** — play audio in the target app while it runs:

```bash
cd Spikes/ProcessTapSpike && swift run ProcessTapSpike com.apple.Music
```

## Installing the driver

The plugin has to live in the system HAL directory, and `coreaudiod` only rescans
that directory on restart. Both steps need admin rights:

```bash
sudo cp -R HALPlugin/build/AudioMixer.driver /Library/Audio/Plug-Ins/HAL/
```

```bash
sudo killall coreaudiod
```

Restarting `coreaudiod` briefly interrupts all audio on the machine. "AudioMixer
Output" should then appear in Audio MIDI Setup and in the Sound preferences output
list. To uninstall, `sudo rm -rf /Library/Audio/Plug-Ins/HAL/AudioMixer.driver` and
restart `coreaudiod` again.

## Status

Working:

- Virtual output device loads in `coreaudiod`, appears as a selectable output, and
  accepts audio without crackling.
- Rust mix math and ring buffer, with tests.
- C ABI for strip create/destroy/gain/mute.
- SwiftUI window with input and output strips, gain sliders, and mute.
- Process-tap approach validated by the spike.

Not wired up yet:

- The driver's internal ring buffer is written but never read back out — it does not
  reach `dsp-engine`.
- App gain/mute controls drive the UI only; they do not call through `mixer-ffi`.
- Strips in the app are placeholders — no real mic input, no live process taps.
- No EQ, compressor, or gate; no routing matrix; no installer.
